# Algorithm descriptions

The challenge requires documenting how any data *generated by the system* is
produced. StormGuard ingests federal data and derives the following. Every
derivation runs in the browser, is deterministic, and uses no AI model. File
references are to `web/src/`.

## 1. Gauge trajectory (rate of rise or fall) — `data/usgs.js`

- Each USGS gauge is fetched with a 4-hour window of 15-minute gage-height
  readings.
- **Rate (ft/hr)** = (latest stage − the reading closest to 1 hour earlier) ÷
  the time between them, rounded to 0.01.
- **Trend:** rate > +0.1 ft/hr is *rising*, rate < −0.1 is *falling*,
  otherwise *steady*. No rate (fewer than 2 readings) is *unknown*.
- Trajectory matters because a gauge rising fast below flood stage can be more
  dangerous than one falling slowly above it, so rising gauges outrank steady
  ones at equal severity.

## 2. Gauge severity — `data/usgs.js`

Fixed stage thresholds: ≥ 30 ft *major*, ≥ 20 ft *moderate*, ≥ 12 ft *minor*,
below that *normal*; no reading is *unknown*.
**Known limitation:** these are not each gauge's official NWS flood stage
(which depends on local datum), so a high-datum gauge such as a reservoir can
show "major". The 13 NWS forecast points (section 3) use NWS's own per-site
flood categories instead.

## 3. NWS forecast crest — `data/ahps.js`, `rulesEngine.js`

- For a curated list of Louisiana / lower-Mississippi forecast points, NWS
  provides the current stage, a forecast stage with valid time, and a flood
  category (action / minor / moderate / major) from that site's own thresholds.
- A point is **worsening** when the forecast category outranks the current one.
- **Hours until crest** = forecast valid time − now. A crest within 24 hours
  moves the point up one tier.

## 4. Alert geometry — `data/nws.js`, `data/zones.js`

Most NWS alerts carry only zone codes, not polygons. Each affected zone's
boundary is fetched from `api.weather.gov/zones`, cached 30 days (boundaries
are static), and the zones are concatenated into one MultiPolygon per alert.

## 5. Affected-population estimate — `data/census.js`, `rulesEngine.js`

- Census tract polygons (TIGERweb, simplified server-side) give a **tract
  centroid** = the plain average of the outer ring's vertices.
- A tract counts as affected when its centroid lies inside the alert polygon
  (even-odd ray-casting point-in-polygon, `geo.js`). The **whole tract's**
  population is then counted.
- Figures per alert: total population (ACS B01003), age 65+ (B01001, 12 age
  bands), households without a vehicle (B25044), mobile-home units (B25024),
  and the share of the state's total population.
- The top-of-panel total takes the **union** across all flood warnings, so a
  tract inside two warnings counts once.
- **Interpretation:** this is "people living in warned zones", an upper bound
  on exposure. It is not people who will flood or people ordered to leave.
- Only flood-related events count (flood, storm surge, tsunami, dam break,
  levee). Fire-weather and wind-only tropical storm warnings still draw on the
  map but add no impact.

## 6. Hospitals at risk — `data/infrastructure.js`, `map/map.js`

OpenStreetMap hospitals (Overpass API). A hospital is "at risk" when it lies
inside a severe or extreme flood-relevant warning polygon (same point-in-polygon
test). FEMA's flood-zone layer is raster tiles, not queryable geometry, so the
active NWS warning polygon is used as the stand-in and this is disclosed in the
app.

## 7. Action tiers (Respond now / Prepare / Monitor) — `rulesEngine.js`

Every signal is placed in one tier and ranked inside it by a score.

- **Warnings:** NWS severity *Extreme* → Respond now; *Severe* → Prepare.
  A warning moves up to Respond now if it contains at least 1 hospital or at
  least 10,000 people.
- **Gauges (major / moderate only):** major and rising → Respond now; major →
  Prepare; moderate and rising → Prepare; moderate → Monitor. A gauge inside a
  warning inherits that warning's area bump (a hospital moves it up a tier;
  10,000+ people lifts Monitor to Prepare).
- **Forecast points:** peak category major → Respond now; moderate → Prepare
  (Respond now if the crest is within 24 h); minor or action → Monitor
  (Prepare if within 24 h); same area bump as gauges.
- **Storms:** a hurricane or tropical system whose track or cone is near the
  area of interest (within 3° of the bounding box) → Prepare, never Respond now,
  because nothing has flooded yet; its value is lead time.
- **Score** orders cards inside a tier: severity base + trajectory (gauges) +
  crest urgency (forecasts) + population/hospital terms.
- "Respond now" is a priority label, not an evacuation order. No federal feed
  carries evacuation orders, and NWS's own text defers to local officials.

## 8. Caching and degradation — `cache.js`, `fetchJson.js`

Each source has a TTL (USGS 5 min, NWS alerts 60 s, NHC 10 min, AHPS 6 h,
Census and hospitals 24 h). If a fetch fails, the last good data is served
flagged "Data delayed". Requests time out (USGS 60 s, others 15 s) and retry
with backoff; each source fails independently so one outage never blanks the
others.

## 9. Test-data injection — `testmode.js`, `public/testdata/`

The "Test scenario" toggle swaps live responses for fixtures (modeled on a
Louisiana flood plus a Category 3 storm) **inside the same fetch → normalize →
rank → render pipeline** the live path uses, so a demo exercises the real
algorithms above. The extra demographic columns in the fixture are
illustrative demo values, not Census figures.
